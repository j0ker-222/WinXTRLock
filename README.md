# winxtrlock

Минимальный блокировщик ввода для Windows 10/11, аналог [`jarun/xtrlock`](https://github.com/jarun/xtrlock) (X11).

Рабочий стол остаётся виден, но клавиатура и мышь заблокированы до ввода пароля от учётной записи - ровно как у оригинала под Linux.

## Как это работает

- ставятся два низкоуровневых хука: `WH_KEYBOARD_LL` и `WH_MOUSE_LL`
- все события клавиатуры и мыши глотаются (курсор замирает - это и есть визуальный признак блокировки, как замок-курсор в xtrlock)
- **никакого перекрывающего окна нет**: рабочий стол и все приложения остаются на экране и продолжают работать (дашборды, графики, логи в реальном времени обновляются как обычно), но ввод до них не доходит
- нажатия накапливаются во внутренний буфер; по `Enter` введённое проверяется через `LogonUser` против текущей учётной записи Windows
- пароль нигде не хранится: удачный `LogonUser` = пароль верный, хуки снимаются, ввод разблокирован
- зависимостей нет, только стандартная библиотека Go

## Использование

```
winxtrlock          заблокировать ввод
winxtrlock -h       справка
```

Отдельный пароль задавать не нужно. Разблокировка: набрать пароль **от своей учётной записи Windows** и нажать `Enter`. `Esc` сбрасывает набранное.

Удобно повесить на ярлык или горячую клавишу, чтобы блокировать одним движением.

## Сборка

```sh
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags "-s -w" -o winxtrlock.exe .
```

В комплекте уже собранные бинарники:
- `winxtrlock.exe` - x86-64 (обычные ПК/ноутбуки)
- `winxtrlock-arm64.exe` - Windows on ARM

## Проверка пароля учётки: нюансы

- проверяется именно **пароль учётной записи** (локальной или доменной), через `LogonUser` с типом `LOGON32_LOGON_NETWORK` - прав администратора для проверки своего же пароля не нужно
- домен берётся из `%USERDOMAIN%` (для локальной учётки это имя компьютера), имя пользователя из `%USERNAME%`
- **PIN и Windows Hello не подходят** - это не пароль учётки. Если вход в систему идёт по PIN/отпечатку/лицу, разблокировать нужно именно текстовым паролем аккаунта
- для **учётной записи Microsoft** проверяется кэшированный пароль MSA; обычно работает, но если пароль недавно менялся онлайн, может потребоваться актуальный
- пустой пароль сетевой логон отклоняет (поведение Windows по умолчанию)

## Важно: это не граница безопасности

`Ctrl+Alt+Del` (Secure Attention Sequence) из пользовательского режима перехватить нельзя - это штатный аварийный выход. Поэтому:

- владелец машины всегда может выйти из блокировки через `Ctrl+Alt+Del` → "Диспетчер задач" и снять процесс
- инструмент **не** ведёт себя как вымогатель и намеренно не пытается стать неубиваемым

То есть это удобный личный "замок" от случайного доступа (отошёл от стола, кот на клавиатуре), но не защита от целенаправленного взлома. Для настоящей защиты используйте штатную блокировку Windows (`Win+L`).

## Ограничения

- хук клавиатуры не видит `Ctrl+Alt+Del` (см. выше) и не ловит некоторые системные сочетания, обрабатываемые ядром
- раскладка учитывается через `ToUnicode` (Shift/CapsLock работают); экзотический IME-ввод не тестировался
